--------------------------------------------------------------------------------
memories_fts is EXTERNAL-CONTENT FTS5.

  - content='memories'        -> FTS reads/writes index tokens but stores no

--------------------------------------------------------------------------------
ZERO triggers exist in the entire database
  (SELECT count(*) FROM sqlite_master WHERE type='trigger'  ->  0)

=> FTS deletes (and inserts/updates) are NOT automatic. There are NO
   AFTER INSERT / AFTER DELETE / AFTER UPDATE triggers keeping memories_fts
   in sync. Synchronization is performed MANUALLY by application code in
   crud.py:

   - On memory create (crud.py:728-736):
       rowid = conn.execute("SELECT rowid FROM memories WHERE id=?", (mid,)).fetchone()[0]
       conn.execute(
         "INSERT INTO memories_fts (rowid, content, memory_type, user_id, agent_name) "
         "VALUES (?, ?, ?, ?, ?)", (rowid, content, type, user_id or '', agent_name or ''))
   - On memory delete (crud.py:859-861) — delete_memory() is a SOFT delete:
       conn.execute("DELETE FROM memories_fts WHERE rowid=?", (row["rowid"],))
       then UPDATE memories SET content='', content_ts='__deleted__', embedding=NULL ...
       (the memories row is retained as a tombstone; the FTS row is hard-deleted).

   CRITICAL IMPLICATION: if rows are deleted from `memories` outside crud.py
   (e.g. direct SQL, or a cleanup script), memories_fts will retain stale
   entries and MATCH queries will return rows whose content no longer exists
   (or NULLs). Any cleanup that deletes memories rows MUST delete the matching
   memories_fts rowids in the same transaction. Conversely, if content is
   updated in place (UPDATE memories SET content=...), the FTS index is NOT
   re-synced — it must be updated manually too.

6) EXACT SQL TO MAP memories rowid -> memories_fts rows  (finding (c))
--------------------------------------------------------------------------------
Because memories_fts is external-content with content_rowid='rowid', the FTS
rowid IS the memories rowid. The mapping SQL is therefore a plain join on rowid:

    SELECT m.rowid, m.id, m.content
    FROM memories_fts f
    JOIN memories m ON m.rowid = f.rowid
    WHERE memories_fts MATCH '<query>';

To delete a memory's FTS entry by memory id:

    DELETE FROM memories_fts WHERE rowid IN (
        SELECT rowid FROM memories WHERE id = ?
    );

To list FTS entries that are stale (memories row deleted but FTS row remains):

    SELECT f.rowid FROM memories_fts f
    LEFT JOIN memories m ON m.rowid = f.rowid
    WHERE m.rowid IS NULL;

Note: for external-content FTS5, DELETE/INSERT on memories_fts is only allowed
with an explicit rowid (INSERT must supply rowid; DELETE must filter by rowid),
and the 'delete' command form is INSERT INTO memories_fts(memories_fts, rowid,
content) VALUES('delete', ?, ...). Plain "DELETE FROM memories_fts WHERE rowid=?"
(as used in crud.py) also works because the rowid is unambiguous.
